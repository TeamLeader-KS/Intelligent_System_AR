# Архитектура Industrial Vision

Backend: presentation → dependency factory → application/use_case → Protocol-port → infrastructure/repository (команды) или infrastructure/queries → frozen DTO (чтения).

Мобильный сценарий: FieldServiceUseCase принимает результаты модели Android, проверяет зарегистрированный по SHA-256 контракт классов и записывает их через существующий жизненный цикл осмотра. Фото прикрепляется автором отдельно; исходный ответ повтора не меняется. PostgresFieldServiceRepository хранит неизменяемые контракты моделей, компоненты и события обслуживания. Нормативный расчёт ресурса и правила интерпретации находок находятся в domain/field_inspections. Старый серверный mock-анализ остаётся отдельным совместимым сценарием. Основной локальный запуск — `docker compose up -d` из `compose.yaml`, без установленного на хосте Go/Python/Android SDK. `compose.local.yaml` относится к дополнительному старому запуску через Go.
Domain/application не импортируют FastAPI, Pydantic или SQLAlchemy. ORM и транзакции портовых операций — в infrastructure; HTTP-схемы и права — в presentation. Сессии и токены отделены от HTTP. AuthService получает AuthStore/Passwords через конструктор.

Frontend: app → domain ← data. Компоненты получают CabinetRepository через контекст; только app/composition создаёт HttpCabinetRepository. Domain содержит модели и контракт, data — fetch и сериализацию.

Стек RS не копируется: FastAPI/Pydantic + SQLAlchemy/Alembic/psycopg, PostgreSQL 17, React/TanStack Query. Данные предметной области и permission-коды RS не используются.

Образ собирается из отдельных backend/ и frontend/. В серверном развёртывании Traefik направляет /industrial-vision на backend, который отдаёт frontend и API; внешние порты самого API не публикуются. В локальном `compose.yaml` API и сайт доступны через порт хоста 8001, чтобы телефон подключался по Wi-Fi. БД подключена только к внутренней сети data, постоянный volume независим от релизов.

Осмотры: InspectionsUseCase → Protocol-порты команд, queries и PhotoStorage. Короткие PostgreSQL-транзакции резервируют ключ повтора и фиксируют результат; анализ и запись фото выполняются вне транзакции. Таблица inspections хранит снимок автора/цеха, исходный hash запроса, состояние обработки, JSON результата/ошибки и метаданные единственного фото. В MVP photo_id совпадает с inspection_id. История отделяет processing_status от оценки оборудования.

PhotoStorage имеет локальную и Nextcloud WebDAV реализации; выбор новых загрузок задаётся PHOTO_STORAGE. Backend и серверный случайный ключ сохраняются с осмотром. Фото выдаются только защищённым API с проверкой цеха и контрольной суммы. Локальные фото находятся в отдельном постоянном volume, не в образе или /tmp. После аварии просроченные PROCESSING переводятся в FAILED с cleanup_pending; активные файлы автоматически не удаляются. TFLite запускается на Android; серверный визуальный анализ через Ollama — отдельный путь с собственными ошибками и проверкой результата.

ReportingUseCase использует порты команд и queries; правила допустимого осмотра и ролей находятся в domain/reporting. PostgreSQL-транзакция создаёт Report, Audit, Issue, Notification и сохранённый ответ ReportRequest. Ключ повтора ограничен автором и осмотром; PostgreSQL transaction advisory lock защищает параллельные повторы. Частичный уникальный индекс группирует открытые проблемы по оборудованию, цеху, дефекту и источнику MOCK/MODEL. Уникальная пара issue/recipient предотвращает повторное внутреннее уведомление. Получатели до появления назначений — активные мастера и инженеры своего цеха. Queries проверяют автора/роль/цех сообщения, а уведомления — конкретного получателя, его текущую роль и цех. FCM пока не подключён.

ReviewUseCase → порты ReviewRepository/ReviewQueries. Review — отдельная добавляемая запись; Inspection.result неизменяем. Domain/reviews строит текущую оценку, сохраняя original_result и latest_review. Последние решения читаются пакетно, без запроса на каждый осмотр. expected_review_id проверяется под блокировкой строки осмотра; WorkflowRequest хранит ответы повторов отдельно для review/close. Закрытие требует актуальной проверки и expected_report_id, сохраняет основание и аудит. Порядок блокировок команд: осмотр → общая advisory-блокировка группы проблемы → строка Issue. Эту блокировку используют и новые сообщения, и закрытие, включая переход к новой группе после ремонта. MOCK и MODEL не смешиваются. FALSE_ALARM отличается от REPAIRED.

Русские описания, теги и примеры OpenAPI находятся в presentation/openapi.py, отдельно от доменных правил и runtime-валидации. Схемы ответа и безопасности формируются FastAPI; документация обогащает их примерами и описанием прав. Примеры проверяются теми же Pydantic-схемами, что HTTP, а ссылки OpenAPI — на разрешимость.

Разделение ролей: администратор — кабинет, ключи, пользователи, справочники и документация; сотрудники — вход /auth/token и API своего цеха. Схема и кабинет не открываются по токену сотрудника. Пароли Argon2, cookie HttpOnly/Secure/Strict, только хеши токенов/ключей в БД. Минимальный healthz используется контейнером.


Текущий локальный запуск: compose.yaml описывает подготовку секретов, PostgreSQL, API/кабинет, bootstrap демо, фоновый Android-сборщик, Ollama и подготовку фиксированных весов. Runtime volumes сохраняют данные, ключ подписи, кеши и серверные веса. Первый запуск требует интернета для образов, зависимостей и модели; работа в локальной сети без интернета требует заранее подготовленного комплекта. Состояние конкретной установки и результаты приёмки проверяются отдельно от наличия Compose-файла. compose.server.yaml остаётся отдельным серверным развёртыванием.

Серверные правила предварительной диагностики — domain/pump_diagnostics; они используют уставки выбранного компонента и явно отмеченные показания. Учёт RUNNING/STOPPED расположен в domain/field_inspections, изменения состояния и записи работ сериализуются блокировкой компонента. Миграция 0002_runtime добавляет состояние работы и заводской номер, не удаляя старые данные. Экспорт PDF/XLSX — infrastructure/inspection_export после авторизованного чтения осмотра.

Android: QR/OCR и CV локальны. Сохранение кадра по кнопке проходит через scoped outbox, одинаковый UUID сохраняется при повторе. Формы работ используют revision. Тип компонента подтверждается вручную; автоматического детектора типов узлов нет.

## Два варианта визуального анализа

Android использует встроенную `ai/models/best_float16.tflite` для визуальных признаков коррозии. Контракт классов привязан к SHA256 файла; отсутствие детекции не подтверждает исправность. Модель не измеряет ток, температуру, вибрацию, остаточный ресурс и не определяет тип узла. Скорость, нагрев и геометрия рамок проверяются на конкретном телефоне.

Серверный путь: `VisionInspectionUseCase` → порт `VisionModel` → `OllamaVision`. В локальной сети отправляется снимок камеры; Ollama использует `qwen3-vl:2b-instruct`. `vision-prepare` получает закреплённый официальный манифест и слои, проверяет размеры и SHA256, публикует кеш атомарно; повторная подготовка проверенного кеша не требует сети. Порт Ollama на хост не опубликован, облачный режим отключён. Подготовка весов и готовность API — разные состояния.

Это экспериментальная универсальная модель, а не обученный и аттестованный детектор всех промышленных дефектов. Она предлагает видимые узлы, рамки и признаки; привязка к компоненту имеет статус `MODEL_PROPOSED`, без привязки — `UNRESOLVED`. Domain/server_vision проверяет известные типы, коды, рамки и принадлежность предложенного компонента карточке. Числовая уверенность не выдумывается: `confidence=null`. Ошибка или некорректный ответ не заменяются нормой либо mock-результатом.

В текущих CPU-прогонах ответ занимал примерно 25–50 секунд. Встречаются пропуски и ложные находки; измерения не подтверждают качество по каждому классу и не гарантируют задержку на другом компьютере. Это отдельный анализ снимка, не покадровый детектор реального времени. Внутренний износ, кавитация, момент затяжки и физические параметры по одному RGB-кадру не устанавливаются; решение требует проверки инженером.

## Источники, справочные ряды и демоданные

[Комплект организаторов](../data/organizers/README.md) сохраняет 84 оригинала, исходные пути, размеры и SHA256. Из 24 PDF извлечён текст 268 страниц, включая OCR 210 сканированных страниц. OCR содержит номера страниц и уверенность слов; это средство поиска, а не подтверждение технических чисел. Полная ручная проверка всех 268 страниц не выполнена.

`data/organizers/structured.json` содержит подготовленные для импорта 9 записей оборудования и семейств: четыре AMS PCP60S12/3, каталоги FCR/HF, две позиции Wilo и семейство из руководства Wilo. Каталожная запись не означает наличие конкретного серийного агрегата. У фактов сохраняются ссылки на документы/страницы и степень проверки. Подготовленный JSON и код импорта не подтверждают, что конкретная запущенная БД уже заполнена; это проверяется отдельно при развёртывании.

Два XLSX содержат по 500 строк, всего 1000 справочных записей. Их исходные листы, номера строк, единицы и авторские диагнозы должны сохраняться. Это `reference`-данные, а не поток датчиков и не реальные осмотры. Совпадение времени и оборотов не доказывает единство физического агрегата; независимая эталонность колонки «Диагноз» не подтверждена. Винтовой AMS с мотором 1460 об/мин и редуктором не объединяется с центробежными рядами около 2950 об/мин; ресурс, нормы и паспортные характеристики не переносятся между ними по аналогии.

Фактические моточасы — отдельные эксплуатационные данные с подтверждённым источником. Исходные демочасы, количество строк в XLSX и календарный возраст документа их не заменяют. Учёт RUNNING/STOPPED отражает события, зарегистрированные в приложении; без подтверждённой начальной наработки он не восстанавливает прошлую работу промышленного агрегата. Импорт справочных рядов не должен увеличивать эти счётчики или создавать вымышленные осмотры.

[Галерея камеры](../ai/demo/pumps/README.md) — отдельный демонстрационный набор: 9 изображений похожих горизонтальных центробежных насосов/узлов, из них 3 реальные и 6 синтетические. Уникальные demo QR/номера служат для наведения камеры и привязки к демокарточке; они не превращают картинку в паспорт физического агрегата. Сюжеты показывают коррозию, жидкость у уплотнения, выступающий крепёж, открытую муфту без кожуха и уровень ниже MIN. Это не независимый размеченный тест, не обучающая выборка и не доказательство поддержки всех дефектов.

Оригиналы `data/organizers/raw/` исключены из Git и восстанавливаются после клонирования через `data/organizers/tools/download_sources.py` по [инструкции](../data/organizers/README.md). Загрузчик использует фиксированный публичный источник и HTTPS API Яндекс Диска, сверяет размер/SHA256, пропускает готовые файлы и не сохраняет подписанные временные ссылки. До офлайн-запуска исходники и модели необходимо подготовить; открытая лицензия на весь комплект организаторов не заявлена.
