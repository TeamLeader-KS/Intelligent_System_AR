# Industrial Vision — запуск через Docker

Локальный сервер, веб-кабинет и Android-приложение для осмотра оборудования. На компьютере нужны **Git и запущенный Docker с Compose v2 или новее**. Go, Python, Java, Android Studio и Android SDK устанавливать не нужно: зависимости работают внутри контейнеров.

## Подготовка компьютера

- **Windows 10/11:** Docker Desktop с WSL 2, режим Linux containers. Команды можно выполнять в PowerShell.
- **macOS:** Docker Desktop. На Apple Silicon сборщик Android работает через эмуляцию amd64 и может быть медленнее.
- **Linux:** Docker Engine, Compose plugin и доступ пользователя к Docker.

Перед запуском откройте Docker Desktop и дождитесь готовности движка. На Linux запустите службу Docker. Проверьте:

```bash
docker info
docker compose version
```

Первая сборка требует интернета для загрузки образов и зависимостей. После подготовки сайт, API и модель работают в локальной сети без интернета. Здесь проверяется Linux; Windows и macOS требуют отдельной проверки на этих системах.

## Скачать и запустить

```bash
git clone -b feat/complete-mvp https://github.com/TeamLeader-KS/Intelligent_System_AR.git
cd Intelligent_System_AR
docker compose up -d
```

Если проект уже скачан, выполните из его корня только:

```bash
docker compose up -d
```

При первом запуске Compose сам собирает недостающие образы. Контейнеры создают случайные пароли, PostgreSQL, схему базы, демонасос и пользователей. Сайт и API запускаются отдельно от фоновой загрузки Android SDK и сборки APK. Завершение команды не означает, что APK уже готов.

Откройте на компьютере **http://localhost:8001/industrial-vision/**. На странице появится статус «APK собирается», затем кнопка скачивания. Если сборка не удалась, сайт остаётся доступен.

## Логины и пароли

```bash
docker compose logs bootstrap
```

В журнале подготовки будут:

```text
Администратор: demo_admin / <пароль администратора>
Android: pump_worker или pump_engineer / <пароль сотрудников>
```

Для сайта используйте администратора, для Android — сотрудника. Пароли автоматически сохраняются в Docker volume `secrets`. При повторном запуске они сохраняются; существующие аккаунты и наработка не сбрасываются. Журнал содержит пароли — не публикуйте его целиком.

## APK и телефон

1. Подключите телефон и компьютер к одной Wi-Fi-сети.
2. Узнайте Wi-Fi IPv4 компьютера: `ipconfig` в Windows, настройки сети в macOS или `ip -4 addr` в Linux.
3. Откройте на телефоне `http://<IP компьютера>:8001/industrial-vision/`.
4. Дождитесь кнопки «Скачать APK», установите приложение и разрешите камеру и доступ к локальной сети, если система спросит.
5. Приложение ищет сервер через HTTP в Wi-Fi-подсети. Отдельную программу на компьютере держать открытой не нужно. Войдите как `pump_worker`.
6. Откройте на ноутбуке ссылку «QR и шильдик для камеры»: QR содержит `pump_demo_001`, заводской номер — `DEMO-PUMP-2026-001`. В приложении используйте QR или «Считать шильдик» и подтвердите точный номер.
7. Выберите компонент. Для демонстрации откройте на ноутбуке «Пример насоса для камеры», наведите телефон на крупный план и нажмите сохранение осмотра. Сохраняется текущий результат и снимок живой камеры; загрузки фотографии из галереи нет.
8. Для регистрации проверки, обслуживания, замены и пуска/останова войдите как `pump_engineer`. Рабочему доступно сохранение осмотра. История и выгрузка PDF/Excel доступны в карточке.
9. Если сеть пропала при отправке, операция останется в локальной очереди. После восстановления связи повторите отправку: UUID и снимок сохраняются, дубли не создаются.

Разрешите входящий TCP 8001 в брандмауэре для частной сети. VPN, гостевой Wi-Fi и изоляция устройств могут мешать подключению. Проверка: `http://<IP компьютера>:8001/healthz` должна вернуть `{"status":"ok"}`. Автопоиск Android рассчитан на порт 8001 и текущую /24-подсеть; в других сетях он может не найти сервер.

Кабинет администратора по умолчанию настроен на `http://localhost:8001`. Скачивание APK и вход сотрудника с телефона доступны по LAN-IP. Если нужен **веб-кабинет администратора по LAN-IP**, создайте `.env` рядом с `compose.yaml`:

```dotenv
IV_LOCAL_ORIGIN=http://192.168.1.50:8001
```

Укажите свой IP и повторите `docker compose up -d`. После этого открывайте кабинет именно по указанному адресу.

## Повторный запуск, обновление и логи

```bash
# Запустить снова с сохранёнными данными и кешем:
docker compose up -d

# После получения новых исходников пересобрать образы:
git pull --ff-only
docker compose up -d --build

# Статус контейнеров:
docker compose ps -a

# Прогресс APK:
docker compose logs -f apk

# Ошибки API и подготовки пользователей:
docker compose logs backend bootstrap setup

# Остановить, сохранив данные:
docker compose stop
```

SDK, Gradle, ключ тестовой подписи, база, фотографии и APK сохраняются в отдельных Docker volumes. Если исходники Android, модель и файл APK не менялись, сборщик повторно использует готовый APK. После обновления мобильного кода выполните `docker compose up -d --build`: команда обновит образ сборщика.

Не удаляйте volumes, если нужны данные и пароли. `docker compose down -v` удаляет и базу, и пароли, и кеши. Старый запуск через Go использует отдельный проект `iv-local`; перед переходом остановите его, чтобы освободить порт 8001. Его база не переносится в новую демонстрационную установку автоматически.

## Makefile — по желанию

Если установлен Make, доступны короткие команды. Для основного запуска Make не требуется.

```bash
make up           # docker compose up -d
make credentials  # логины и пароли
make logs         # логи API, APK и подготовки
make stop         # остановить контейнеры
```

## Что работает

Создаются один условный насос `pump_demo_001`, три компонента, параметры и наработка, явно отмеченные как **ДЕМО**. Они не получены от реальных датчиков. Фиктивные осмотры не создаются.

Работают роли и авторизация, доступ по цехам, карточки, история, серверный приём результатов модели и учёт обслуживания. Модель `ai/models/best_float16.tflite` встраивается в APK и распознаёт дефекты живой камерой на телефоне. Порог строго выше 0,4; «Без коррозии» исключается из дефектов, неподтверждённый 13-й класс отображается как неизвестный. Отсутствие рамок не подтверждает исправность.

Осмотр сохраняется **по кнопке**, вместе с кадром и выбранным компонентом. QR читается встроенным ZXing, латинский шильдик — встроенной OCR-моделью ML Kit; при первом использовании скачивать модель не нужно. Тип узла текущая TFLite сама не определяет: привязка к компоненту выполняется инженером, это ограничение прототипа.

В кабинете раздел «Осмотры и обслуживание» показывает карточки, нормы, историю, работы и диагностические сценарии. Состояние RUNNING увеличивает моточасы по времени сервера, STOPPED — нет. При замене счётчик нового компонента начинается с нуля; обслуживание работающего компонента требует его остановки. Доступны PDF и XLSX.

## Готовые данные для демонстрации

При запуске автоматически создаются:

- насос `pump_demo_001`, заводской номер `DEMO-PUMP-2026-001`, три компонента;
- сотрудники `pump_worker` / `pump_engineer` и администратор `demo_admin`;
- примеры ручной проверки компонентов, явно помеченные как синтетические;
- нормативы и уставки, принятые командой исключительно для демо;
- контракт встроенной модели: 12 известных меток и неизвестный класс 12.

Во вкладке «Осмотры и обслуживание» выберите подшипниковый узел, загрузите сценарии и проверьте кавитацию, смазку, расцентровку, утечку, крепления, масло, токи, давление или защитный кожух. Сценарии не запускают CV и не сохраняются как реальные осмотры. Показания имеют источник DEMO, визуальные замечания — MANUAL. Для ТО выполните явную запись работ; данные пользователя при следующем старте не сбрасываются.

## Модель и ограничения

Рабочая TFLite Софии остаётся исходной. [Подготовка данных и обучение](ai/training/README.md) содержит воспроизводимый процесс; [карточка экспериментального кандидата](ai/candidates/spiderbot-cpu-finetune/MODEL_CARD.md) — результаты реального CPU-дообучения другой открытой базы. Кандидат не установлен в APK: качество на контрольной выборке оказалось недостаточным. Это не подтверждённое улучшение модели насосов.

Обязательна проверка на реальном телефоне: чтение вашей таблички, геометрия рамок, скорость, нагрев и весь сценарий без интернета. Автоматическое распознавание типов узлов и подтверждённое качество на реальных насосах остаются открытыми пунктами; не заявляйте 100% выполнения ТЗ по одной успешной сборке.

## Документация и другие способы запуска

- [Android/API и ресурсы компонентов](docs/offline-android.md).
- [Архитектура](docs/architecture.md).
- Swagger: `http://localhost:8001/industrial-vision/docs` после входа администратора. JS/CSS Swagger пока загружаются с CDN.

Старый запуск `go run deploy/local/main.go` остаётся дополнительным вариантом с быстрым UDP-поиском и `compose.local.yaml`; он требует Go 1.20 или новее. Основной Docker-сценарий выше Go не требует. Рабочее серверное развёртывание использует отдельный `compose.server.yaml`; файл `compose.yaml` теперь предназначен для локального демо.
