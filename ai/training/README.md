# Дообучение модели насосов

Текущая `ai/models/best_float16.tflite` остаётся рабочей моделью Android. Она не изменяется этими командами. Это экспорт для распознавания, исходный `best.pt` и размеченный набор Софии в доступных файлах не найдены. На этой машине NVIDIA-драйвер пока не отвечает. Отдельный публичный YOLOv8n-кандидат реально дообучен на CPU: 9 эпох с ранней остановкой, 20 train / 5 validation / 6 test после фильтрации. Качество на отложенных общих поверхностях низкое; к замене рабочей модели он не рекомендован. См. [model card и фактические метрики](../candidates/spiderbot-cpu-finetune/MODEL_CARD.md).

## Подготовка данных

Скопируйте [manifest.example.json](manifest.example.json) рядом с изображениями и YOLO-разметкой. Обязательны источник и лицензия, признак реального/синтетического изображения, группа физического насоса и отметка ручной проверки. Пример намеренно не проходит проверку: в нём нет настоящих изображений и подтверждённой разметки.

Каждая строка label-файла: `class_id x_center y_center width height`, координаты 0…1. Для проверенного исправного изображения нужен пустой label-файл и `negative: true`. Пустой/отсутствующий файл без явной проверки не становится автоматически исправным примером. Класс `pitting` допустим только при подтверждённой разметке точечной коррозии; по цвету ржавчины его не определяют.

Все ракурсы, кадры видео, обрезки и повторные съёмки одного насоса получают одинаковый `equipment_group`. Одинаковые сцены из разных источников тоже объединяются. Синтетические изображения используются только для train; тест должен содержать реальные независимые насосы. Автоматически проверяются точные дубликаты декодированных пикселей; похожие кадры нужно просмотреть вручную.

```bash
python -m venv .venv-training
# Активируйте окружение средствами своей ОС.
python -m pip install -r ai/training/requirements.txt
python ai/training/prepare_dataset.py ai/dataset/manifest.json ai/dataset/prepared-v1
```

Скрипт разделяет **группы оборудования**, а не отдельные фото, сохраняет seed=102 и происхождение файлов. Для воспроизводимого ручного разделения задайте `split` (`train`, `val`, `test`) у всех записей. Подготовка откажется при утечке групп, неподтверждённых данных, неверных рамках или отсутствии реальных отрицательных примеров и примеров каждого класса в любой из трёх частей. Три группы — технический минимум разделения, а не достаточный размер обучающего набора.

## Обучение кандидата

```bash
python ai/training/train.py ai/dataset/prepared-v1 --weights ai/checkpoints/best.pt --output ai/runs/pump-v1 --epochs 30 --batch 4 --device cpu
```

Для работающего CUDA используйте `--device 0`. Исходный checkpoint должен быть доверенным: `.pt` может содержать исполняемую сериализацию. Порядок классов должен совпадать с датасетом. `--allow-new-head` разрешает новый набор классов, но результат тогда требует отдельной интеграции в Android. Три класса из примера не соответствуют текущим 13 выходным каналам Android-модели.

На train настраиваются веса, val используется для выбора эпохи; test запускается после выбора лучшей эпохи. Если по test снова меняются гиперпараметры, этот набор уже нельзя считать независимым итоговым тестом. Сохраняются реальные test-метрики, seed, SHA исходных весов/манифеста и точные установленные версии окружения. GPU/ОС могут влиять на численную воспроизводимость.

`--export` экспортирует отдельного кандидата `.tflite` с входом 640, batch=1, без встроенного NMS. Экспорт может установить дополнительные зависимости конвертера. Автоматического копирования в `ai/models/` нет: сначала сравните старую и новую модели на одних реальных насосах, проверьте форму тензора, порядок классов, recall/ложные тревоги и задержку на телефоне. Затем согласуйте новый SHA и контракт бэкенда. В `candidate-report.json` совместимость намеренно остаётся `apk_compatible: false` до этой проверки.

Проверки валидатора без установки PyTorch:

```bash
python -m unittest discover -s ai/training -p 'test_*.py'
```

API обучения и экспорта проверены по [документации Ultralytics Train](https://docs.ultralytics.com/modes/train/) и [TFLite](https://docs.ultralytics.com/integrations/tflite/). Зафиксирован [Ultralytics 8.3.228](https://pypi.org/project/ultralytics/8.3.228/), без перехода существующего приложения на новую семью моделей. Все транзитивные версии фиксируются в отчёте фактического запуска; обучение пока не запускалось.

## Доступные источники

Подбор готовых весов и датасетов — [sources.json](sources.json). Обнаруженные три реальных фото насосов из прежней проверки доступны в локальной `ai/dataset/references/`, но **без разметки и подтверждённых прав на обучение**. Они не включены в train/val/test. Демоизображения Qwen в `ai/demo` также не являются независимым тестовым набором.

Для отдельной технической проверки можно скачать небольшой открытый набор с существующими YOLO-рамками:

```bash
python ai/training/download_public_smoke.py ai/dataset/public-corrosion-smoke --count 24
```

Это 24 пары изображение/разметка из test-раздела Roboflow 100 corrosion-bi3q3 (зеркало LibreYOLO, CC BY 4.0). Downloader фиксирует revision и проверяет размеры и SHA каждого файла. Классы источника: `Slippage`, `corrosion`, `crack`; датасет не предназначен специально для насосов. Его не следует использовать для обучения и затем объявлять независимым тестом. Пары скачаны локально; физические группы и соответствие целевым насосам не подтверждены.

## Отдельный короткий CPU-прогон

Для проверки механизма обучения без NVIDIA можно собрать **необязательный** образ. Это не часть обычного `docker compose up`: приложение его не скачивает и не использует.

```bash
docker build -f ai/training/Dockerfile -t iv-corrosion-training:local ai/training
python ai/training/download_candidate.py
python ai/training/download_public_smoke.py ai/dataset/public-corrosion-train --count 24 --split train
python ai/training/download_public_smoke.py ai/dataset/public-corrosion-valid --count 12 --split valid
```

`cpu_smoke.py` берёт только кадры, где все размеченные объекты имеют исходный класс `corrosion` (1), и переносит его в единственный класс `Corrosion` (0) модели SpiderBot v1. Кадры со смешанной разметкой исключаются полностью. Этот технический прогон не заменяет основной строгий pipeline выше: источник не содержит проверенных групп насосов и отрицательных примеров для нашего сценария. Текущий `.tflite` не меняется.

Модель `.pt` запускается только в отдельном контейнере: без сети, без привилегий и секретов, с read-only входами и отдельной выходной папкой. Для Linux (пути и UID/GID адаптируйте под свою ОС):

```bash
mkdir -p /tmp/iv-cpu-training-output
docker run --rm --network none --cap-drop ALL --security-opt no-new-privileges --read-only --tmpfs /tmp:size=2g,mode=1777 --memory 5g --cpus 4 --user "$(id -u):$(id -g)" -v "$PWD/ai:/inputs:ro" -v /tmp/iv-cpu-training-output:/outputs iv-corrosion-training:local python /inputs/training/cpu_smoke.py /inputs /outputs --epochs 1
```

Результат — отдельные `.pt`, `results.csv` с реальной эпохой и `smoke-report.json`. Значения validation на нескольких общих изображениях не доказывают улучшение распознавания насосов. Нужен независимый целевой тест; исходная модель Android остаётся прежней.

Для ограниченного эксперимента вместо `--epochs 1` допускается `--epochs 20 --patience 5 --evaluate-test`: сначала вычисляется baseline на validation, лучшая эпоха выбирается только по validation, затем отложенный test проверяется один раз. Checkpoint перед baseline и перед обучением загружается отдельно. Названия групп оборудования у исходного публичного датасета неизвестны, поэтому эти результаты нельзя называть достоверной оценкой для насосов.

Открытые данные коррозии полезны как дополнительные поверхности; они не заменяют фотографии целевых насосов. Нельзя автоматически перенести segmentation masks, классификационные метки и группы коррозии в нужные bounding boxes/классы без проверки. Изображение ржавчины не доказывает утечку, кавитацию, перегрев или внутренний износ.
