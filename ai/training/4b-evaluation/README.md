# Изолированная оценка Qwen3-VL 4B

Кандидат: официальный `qwen3-vl:4b-instruct`, Q4_K_M. Манифест `84f7ed8042fa7cdbd902f7dcb7d0370e032095047cc3244179f263b77b5bc318`, суммарно 3 337 225 651 байт. Лицензия Apache-2.0 сохранена из официального слоя и проверена по SHA-256. Источник: https://ollama.com/library/qwen3-vl:4b-instruct . Полные ссылки, размеры и SHA слоёв — `candidate.json` и `official-manifest.json`.

## Подготовка

Эксперимент не меняет `deploy/vision_prepare.py`, его SUPPORTED/PIN, переменную VISION_MODEL, конфигурацию Compose, Android или рабочий 2B-тег. Большие файлы остаются в существующем Docker volume Ollama, не в Git и не в `/tmp`. До запуска нужно проверить свободное место именно на файловой системе volume.

В текущем окружении каталог `blobs` и каталог манифестов принадлежат UID/GID 1000. В контейнере подготовки отключены capabilities, поэтому даже UID0 не обходит права владельца. Две первые попытки завершились PermissionError до загрузки весов; логи сохраняются локально в `.local-testing/ai-cache` и не предназначены для Git. Права каталогов не менялись. Для другого окружения сначала определить владельца cache, а не копировать UID вслепую.

```sh
docker compose run --rm --no-deps --user 1000:1000 -T vision-prepare python - < ai/training/4b-evaluation/prepare_in_container.py
```

Скрипт работает с текущим cache: удерживает существующий `.vision-prepare.lock` через read-only descriptor и `flock`, проверяет официальный манифест по полному закреплённому SHA, использует проверенные функции HTTPS-загрузки из `/app/vision_prepare.py`. Разрешены только registry.ollama.ai и подписанные HTTPS R2-redirects. Каждый слой проверяется по точному размеру и SHA, затем атомарно публикуется. Новый манифест 4B появляется только после проверки всех слоёв; существующий отличный 4B-манифест не перезаписывается. Проверяется неизменность SHA 2B-манифеста.

## Три реальные разработческие пробы

После полной подготовки, последовательно и при свободном Ollama:

```sh
docker compose exec -T backend python - < ai/training/4b-evaluation/evaluate_in_backend.py > ai/training/4b-evaluation/results.jsonl
```

Это существующий production `OllamaVision` с **неизменённым рабочим промптом и схемой**, отдельным аргументом модели 4B и таймаутом 240 секунд. Временная обёртка HTTP в памяти процесса только записывает SHA/ответ, не заменяет промпт. Сохранены исходные параметры temperature0, num_predict900, num_ctx4096 и подготовка изображения thumbnail768/JPEG90. До первого запроса проверяется полный digest 4B.

Максимум три знакомых разработчикам изображения: KSB, синтетическая открытая муфта, синтетическое масло ниже MIN. SHA совпадают с соответствующими исходниками прошлого эксперимента; снимки неизвестных пользователей не отправляются. `components=[]` исключает подсказки карточки, но не проверяет привязку ID. Осмотры в БД не создаются. Настройки рабочего backend остаются 2B.

JSONL фиксирует digest модели, SHA источника, промпта, схемы и адаптера, полный реальный ответ/ошибку, время сервера и полное время запроса. Это не независимый тест точности: два изображения синтетические, human-approved ground truth нет, mAP/проценты готовности не вычисляются. Предыдущий `prompt-experiment-v1` менял промпт, поэтому его результаты нельзя использовать как парную оценку выигрыша 4B против 2B. Полезность оценивается по конкретным видимым наблюдениям и ошибкам, не по корректности JSON.

## Итог реальной проверки

Кандидат **не принят как улучшение рабочего распознавания дефектов**. Все три ответа получены без ошибок API/схемы, но правильный JSON не гарантирует правильный вывод:

| Проба | Полное время | Наблюдение |
|---|---:|---|
| KSB | 76,700 с | Насос/мотор локализованы, дополнительных дефектов нет. |
| Открытая муфта, синтетика | 85,052 с | guard_missing пропущен; вместо него общие признаки повреждения поверхности рамы/крепежа. |
| Масло ниже MIN, синтетика | 79,133 с | Стекло локализовано, но названо уплотнением и surface_damage; oil_abnormal/уровень ниже MIN не отмечены. |

Описание всех ответов на английском вопреки инструкции на русский. Это разработческие наблюдения, не метрики качества. 4B остаётся отдельным исследовательским тегом в Docker-кеше; production VISION_MODEL и SHA манифеста2B неизменны. Итог и разложение серверного времени — `report.json`. Полный исходный JSONL сохранён; поле request_image_sha256 в нём относится к base64-тексту изображения в запросе, source_sha256 — к оригинальным байтам файла. Сырые логи подготовки перенесены в `.local-testing/ai-cache` и не предназначены для Git.
